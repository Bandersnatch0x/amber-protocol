# Glossary

This page is a **local summary** of a few frequently-referenced terms. The
authoritative, complete terminology surface for Amber Protocol is
[`CONTEXT.md`](../../CONTEXT.md) at the repository root (issues/0152, 裁决 9):
add or change term definitions there — not here — and treat this page only as a
short pointer for readers who land in the wiki first.

| Term | Summary | Authoritative definition |
| --- | --- | --- |
| Harness | An architecture role name (policy, capability, context, evidence, replay, run) realized by Amber Core plus governed adapters — not a product component. | [`CONTEXT.md`](../../CONTEXT.md) |
| Feature State | Machine-readable feature status, read only from `feature_list.json`. | [`CONTEXT.md`](../../CONTEXT.md) |
| Evidence | The deterministic, replayable proof bound to a claim before a feature is marked `passing`. | [`CONTEXT.md`](../../CONTEXT.md) |

> For every other term (Distributed Governance, Storage/Read Model, Compatibility,
> the Governance Tracer Scenario, and ~200 more), see `CONTEXT.md`. This summary is
> intentionally partial and never a second source of truth.
